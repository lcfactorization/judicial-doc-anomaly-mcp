# 输出格式规范

## 报告格式规范（Report Format Standards）

> [!IMPORTANT]
> 以下格式规范适用于所有提交法院或合议庭的正式报告，必须严格遵守。

### 一、总结/归纳/点评：优先使用表格

所有涉及多点罗列的总结、归纳、点评内容，**必须优先使用表格**呈现：

| 适用场景 | 表格类型 | 示例 |
|:---|:---|:---|
| 异常项罗列 | 序号+异常项+置信度+严重程度+翻案价值 | 第十章各维度详细清单 |
| 类案对比 | 案号+法院+裁判要旨+与本案一致性 | 第六章类案检索 |
| 法律依据对照 | 法条+核心内容+本案适用+符合情况 | 第二章法律适用分析 |
| 证据对照 | 证据编号+证据内容+判决处理+应有效力 | 第二章证据采信分析 |
| 多维验证 | 验证维度+参照基准+本案结果+偏离程度 | 第十章偏离度验证 |
| 综合判定 | 判定条件+阈值+本案数值+是否满足 | 第十章结构性偏差判定 |
| 评分汇总 | 维度+权重+得分+扣分项+加分项 | 质量评估章节 |

### 二、无法表格处：使用GitHub Alerts

当内容不适合表格时，使用以下GitHub Alerts类型（Typora早期版本完全支持）：

| Alert类型 | 适用场景 | 示例 |
|:---|:---|:---|
| `[!CAUTION]` | 关键结论、高风险警告、结构性偏差判定 | 综合异常等级、偏离度验证结论 |
| `[!WARNING]` | 单个异常项的法理点评、证据对照 | 各异常项的深度剖析 |
| `[!IMPORTANT]` | 核心法理、重要说明、跨维度耦合分析 | 法律依据核心结论、耦合关系说明 |
| `[!NOTE]` | 补充说明、交叉索引、次要维度点评 | 程序类点评、材料完整性说明 |
| `[!TIP]` | 实务建议、行动指南、翻案策略 | 救济路径、翻案速查表使用说明 |

### 三、多项目耦合：表格+Alert组合

当多个异常项之间存在耦合关系时，使用以下组合格式：

```
| 耦合编号 | 触发维度 | 异常项 | 耦合关系 | 综合风险 |
|:---|:---|:---|:---|:---|
| C-01 | D2+D3 | 证据双标+事实跳跃 | 强耦合 | 高度可能 |

> [!CAUTION]
> **耦合分析**：上述异常项形成证据-事实-法律的完整偏差链，单一异常不足以说明问题，但三者耦合指向结构性偏差。
```

### 四、异常耦合分析专用格式

| 耦合编号 | 触发维度及异常项 | 耦合等级 | 指向获益方 | 综合风险评级 |
|:---|:---|:---|:---|:---|
| C-01 | D2(证据双标)+D3(事实跳跃) | 强 | 被告 | 高度可能 |
| C-02 | D5(法律适用)+D8(说理缺失) | 中 | 被告 | 可能 |

### 五、提交合议庭内容：使用0缩进HTML代码

提交合议庭的正式内容（如情况说明、补充意见等），必须使用**0缩进HTML代码**格式：

```html
<div style="font-family: SimSun, serif; font-size: 16px; line-height: 1.8; max-width: 800px; margin: 0 auto;">

<h2 style="text-align: center;">关于XXX号案的情况说明</h2>

<p style="text-indent: 2em;">尊敬的合议庭：</p>

<p style="text-indent: 2em;">上诉人就本案相关情况，向合议庭说明如下：</p>

<h3>一、关于用人单位特定行为合法性认定</h3>

<p style="text-indent: 2em;">一审判决已正确认定被告对原告的特定管理行为违法，上诉人对此予以认可。该认定符合相关法律规定，体现了对劳动者权益的保护。</p>

<h3>二、关于非典型法律关系认定</h3>

<p style="text-indent: 2em;">一审判决已正确认定原告与关联单位之间构成非典型法律关系（如混同用工/双重劳动关系），上诉人对此予以认可。该认定符合相关法律规定精神。</p>

</div>
```

**HTML格式要求**：
- 所有HTML标签必须0缩进（顶格书写）
- 使用内联style，不使用外部CSS
- 字体使用SimSun（宋体），字号16px
- 段落使用 `text-indent: 2em` 首行缩进
- 标题使用 `<h2>` 或 `<h3>`，居中或左对齐
- 禁止使用JavaScript
- 禁止使用外部资源引用

### 六、签名档：完整使用指定模板

报告结尾的签名档，必须**完整使用** `证据材料/此致[匿名化市]中级人民法院签名档.md` 文件的全部内容，**不得截取、不得修改结构、不得省略任何部分**。

签名档使用规则：
1. **完整引用**：将签名档文件的全部HTML代码完整复制到报告结尾
2. **日期动态更新**：将签名档中的日期替换为**当前日期**（格式：YYYY年M月D日）
3. **路径保留**：签名图片的 `background-image` URL 路径保持不变
4. **结构不变**：`此致`、`[匿名化市]中级人民法院`、`上诉人：XXX` 的结构和样式完全保留

### 七、禁止的格式

- ❌ 禁止使用Markdown代码块包裹HTML内容（提交合议庭的HTML应直接以HTML标签开始）
- ❌ 禁止在HTML中使用缩进（必须0缩进）
- ❌ 禁止使用 `[!CAUTION]` 等GitHub Alerts包裹表格（表格应独立使用）
- ❌ 禁止在表格内嵌套Alert
- ❌ 禁止使用emoji（除非用户明确要求）
- ❌ 禁止截取签名档的部分内容——必须完整使用整个文件

## 维度检测结果格式
每个维度的检测结果必须包含以下字段：

### 通用异常项格式
- **异常项名称**
- **具体表现**（引用原文段落，标注页码/段落/行号）
- **指向获益方**（原告/被告/双方/无）
- **异常程度**（疑似/可能/高度可能/确定）
- **法理分析**（引用具体法条）
- **A系列分类编号**（A1-A8）
- **反向校验结果**
- **净异常判定**（成立/存疑/不成立）

### 事实认定维度特殊格式
- **编号**（F-01至F-26）
- **异常表现**（引用原文段落+证据编号）
- **翻案权重**（★数量）
- **异常程度**（疑似/可能/高度可能/确定）
- **法理分析**

### 耦合分析格式
- **耦合等级**（弱/中/强/结构性偏差）
- **触发维度及异常项**
- **指向获益方**
- **综合风险评级**

## 报告模板变量
报告生成时使用以下变量替换：

| 变量 | 说明 |
|------|------|
| `{{report_id}}` | 报告编号 |
| `{{case_name}}` | 案件名称 |
| `{{doc_type}}` | 文书类型 |
| `{{detection_time}}` | 检测时间 |
| `{{model_name}}` | 分析模型 |
| `{{completeness_score}}` | 材料完整性评分 |
| `{{version}}` | 引擎版本 |
| `{{risk_level}}` | 综合异常等级 |
| `{{risk_reason}}` | 风险原因 |
| `{{anomaly_table}}` | 异常总览表 |
| `{{dimension_details}}` | 分维度详情 |
| `{{adversarial_table}}` | 对抗校验汇总 |
| `{{coupling_analysis}}` | 耦合分析 |
| `{{quality_score_table}}` | 质量评估 |
| `{{quick_check_results}}` | 翻案速查结果 |
| `{{remedies}}` | 救济路径建议 |
| `{{signature_block}}` | 签名档（完整引用签名档文件，日期动态更新） |
